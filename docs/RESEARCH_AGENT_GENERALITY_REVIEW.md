# Research Analyst 通用性审查

## 文档目的

当前 `research-analyst` 的目标是：

- 更关注 MMKB 本地知识库；
- 在需要本地证据时可靠使用 `rag_*` 工具；
- 同时保留通用 Agent 的任务处理能力。

本文记录当前提示词、Skill 和 Agent 配置中可能削弱通用性的主要问题，
以及可供后续讨论的改进方案。本轮仅整理分析，不修改现有运行行为。

## 当前相关配置

主要相关文件：

- `backend/.deer-flow/agents/research-analyst/SOUL.md`
- `.deer-flow/agents/research-analyst/SOUL.md`
- `backend/.deer-flow/agents/research-analyst/config.yaml`
- `.deer-flow/agents/research-analyst/config.yaml`
- `skills/custom/local-deep-research/SKILL.md`
- `skills/custom/local-systematic-literature-review/SKILL.md`

当前 Agent 已启用的 Skill：

```yaml
skills:
  - local-deep-research
  - local-systematic-literature-review
  - ppt-generation
```

## 总体结论

当前配置没有要求所有任务必须按照某个固定顺序调用 `rag_*` 工具。

但是，`SOUL.md`、本地研究 Skill 的触发描述和 Agent Skill 白名单叠加后，
存在明显的本地研究流程过度触发风险。普通知识问答、编程协助、写作和外部
信息查询可能被错误引导为本地深度研究任务，导致响应变慢、工具调用过多，
并削弱通用 Agent 能力。

## 主要问题

### 1. 本地知识库的触发条件过宽

当前 `SOUL.md` 要求：

> 当问题可能由本地文档回答时，将本地知识库视为主要证据来源。

“可能由本地文档回答”缺少明确边界。几乎所有知识问题都可能满足这一条件，
因此模型可能对普通任务也优先调用 RAG。

可能受到影响的任务包括：

- 普通寒暄；
- 通用编程问题；
- 文本润色、翻译和写作；
- 架构设计与头脑风暴；
- 不依赖本地资料的概念解释。

建议将触发条件收窄为：

- 用户明确要求使用本地知识库、已上传文档或指定文档；
- 当前对话明确围绕本地文档展开；
- 任务必须引用本地证据才能可靠完成；
- Agent 已有充分理由判断本地知识库与问题直接相关。

### 2. 网页搜索被普遍限制为本地知识库的补充

当前 `SOUL.md` 要求使用网页工具前先判断本地知识库是否能回答，并将网页
搜索定位为有限的外部补充。

这适合本地知识研究任务，但不适合所有任务。例如：

- 用户明确要求搜索互联网；
- 查询最新新闻、政策、价格或软件版本；
- 本地知识库与主题无关；
- 需要验证公开资料或官方文档。

建议仅在“本地知识任务模式”中限制网页搜索。对于普通任务和明确的外部信息
任务，应允许 Agent 直接选择网页工具。

### 3. `local-deep-research` 的触发描述过宽

当前 Skill 将以下情况列为始终加载：

- 用户询问 `what is X`、`explain X`、`research X`；
- 用户只给出一个宽泛主题；
- 用户询问某个概念、项目或架构；
- 单次检索不足以回答。

这些描述覆盖大量普通问题。一旦 Skill 被加载，它又要求多组查询、多角度
拆解、文档预览和证据验证，容易把简单问题扩大为耗时的研究流程。

建议明确规定：

- 只有本地知识库已经被明确选为主要证据源时，才加载
  `local-deep-research`；
- 普通概念解释和简单事实查询不应仅因问题较宽泛而触发该 Skill；
- 简单本地查询允许直接调用一次或少量 `rag_*` 工具，不必加载完整研究流程；
- 只有复杂、需要多角度证据综合的本地任务才执行完整深度研究流程。

### 4. Agent Skill 白名单直接削弱通用能力

当前 `research-analyst` 只允许使用三个 Skill。这会阻止 Agent 使用其他已经
安装的通用 Skill，例如：

- `deep-research`
- `data-analysis`
- `academic-paper-review`
- `code-documentation`
- `consulting-analysis`
- 其他适合具体任务的公开 Skill

该限制比 `SOUL.md` 的措辞更直接地影响通用能力。

后续可讨论两种方案：

1. 取消 Agent Skill 白名单，使其继承全部已启用 Skill。
2. 保留白名单，但加入经过筛选的常用通用 Skill。

取消白名单能够获得更强通用性，但会增加 Skill 选择复杂度和系统提示词内容。
保留并扩展白名单更可控，但需要持续维护。

### 5. 输出格式持续偏向研究报告

当前 `SOUL.md` 要求关键判断尽量附本地证据，并在最后陈列来源引用。

对于实际使用本地知识库或网页研究的回答，这是合理要求。但对普通聊天、
写作、编程和执行型任务，它可能导致不必要的正式结构、来源章节或证据声明。

建议将来源与证据格式要求限定为：

- 实际使用了本地 RAG 或网页研究工具；
- 用户要求引用、报告或可追溯证据；
- 回答包含依赖外部事实的强判断。

## 应继续保留的规则

以下规则用于保证安全性、隔离性和结果正确性，不应为了通用性而删除：

- MMKB 本地知识库文档内容只能通过 `rag_*` 工具读取；
- 禁止对 MMKB 返回的服务端路径使用 `grep`、`read_file`、`bash` 或 `ls`；
- 面向用户的本地文档和图片链接只能复制 `rag_*` 返回的现成 URL；
- 不得根据 `document_id` 手写或猜测 URL；
- 用户明确要求本地研究时，应优先使用本地证据；
- 本地多文档系统综述应使用 `local-systematic-literature-review`；
- 应清楚区分本地证据、外部网页内容和模型推断。

这些规则只限制“如何安全、正确地读取本地知识”，不应限制 Agent 处理与本地
知识库无关的任务。

## 建议的任务模式

后续可将 Agent 的任务判断明确划分为三种模式。

### 普通任务模式

适用于：

- 普通知识问答；
- 编程、写作、翻译和分析；
- 文件处理、PPT 生成和执行型任务；
- 明确需要外部信息的任务。

行为：

- 根据任务直接选择通用知识、文件、命令、网页工具或通用 Skill；
- 不主动假设本地知识库包含相关内容；
- 不强制输出本地证据或来源列表。

### 本地知识任务模式

适用于：

- 用户明确提到本地知识库、已上传文档或指定文档；
- 当前对话明确基于本地材料；
- 用户要求回答必须以本地证据为依据。

行为：

- 使用 `rag_*` 工具读取本地知识；
- 简单问题使用最短有效检索路径；
- 复杂、多角度任务才加载 `local-deep-research`；
- 本地证据不足时明确说明，并按用户需求决定是否使用网页补充。

### 本地系统综述模式

适用于：

- 用户明确要求多文档综述、survey、SLR 或 annotated bibliography；
- 需要构建候选文档集合、筛选来源和跨文档主题综合。

行为：

- 加载 `local-systematic-literature-review`；
- 按综述流程执行检索、筛选、抽取和综合；
- 输出证据矩阵、范围、缺口和本地引用。

## 建议的实施范围

如果决定执行改进，建议同步修改以下三层，而不是只修改 `SOUL.md`：

1. `SOUL.md`
   - 收窄本地知识库触发条件；
   - 明确普通任务、本地任务和系统综述的边界；
   - 将网页限制和来源格式要求限定到研究任务。

2. `local-deep-research/SKILL.md`
   - 收窄 Skill 触发描述；
   - 增加简单本地查询的轻量路径；
   - 避免所有本地问题都执行完整深度研究流程。

3. `research-analyst/config.yaml`
   - 重新决定 Skill 白名单策略；
   - 在继承全部 Skill和维护扩展白名单之间做出选择。

## 后续待讨论事项

- `research-analyst` 应继承全部已启用 Skill，还是维护扩展白名单？
- 用户未明确提到本地知识库时，Agent 是否可以主动做一次轻量本地检索？
- 哪些请求应判定为“简单本地查询”，无需加载 `local-deep-research`？
- 网页搜索在本地证据不足时应自动进行，还是先询问用户？
- 普通回答是否需要默认提供来源，还是仅在实际调用研究工具后提供？
- 是否需要为普通任务和本地研究任务分别建立测试提示词集？

## 建议验证用例

后续修改完成后，应至少验证以下场景：

| 测试请求 | 期望行为 |
|---|---|
| “你好” | 直接中文回答，不调用 RAG |
| “Python 如何读取 JSON？” | 直接回答，不调用 RAG |
| “帮我润色这段文字” | 直接处理文本，不调用 RAG |
| “搜索最新的 LangGraph 官方版本变化” | 直接使用网页/官方来源，不先调用 RAG |
| “本地知识库中有哪些 NIST 文档？” | 使用少量 `rag_*` 工具，不执行完整深度研究 |
| “根据本地 NIST 文档解释 CSF 2.0” | 使用本地 RAG；按复杂度决定是否加载 `local-deep-research` |
| “基于本地 NIST 文档写系统性综述” | 加载 `local-systematic-literature-review` |
| “基于本地文档生成 PPT” | 使用本地证据和 PPT Skill，不执行无关研究流程 |
